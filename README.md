# Учёт производства свечей и ИИ-ассистент

Мини-система учёта склада и производства для мастерской ароматических свечей и ИИ-ассистент поверх неё. Ассистент отвечает на вопросы по данным учёта, сам ищет информацию и выполняет действия от имени пользователя — только после подтверждения.

- **Учёт.** Сырьё приходит партиями в рублях, долларах и евро, резервируется по FIFO и расходуется на производственные задания. Есть роли, журнал изменений и фоновая отправка отчётов во внешний сервис маркировки.
- **Ассистент.** Чат со стримингом, инструменты поверх того же сервисного слоя, Code Interpreter для расчётов и графиков, псевдонимы вместо имён, память, запасная модель.

## Запуск

Нужен Docker с Compose.

1. Создать файл настроек:
   ```bash
   cp .env.example .env
   ```
2. Вписать в `.env` ключ `OPENAI_API_KEY`. Без ключа учётная часть работает полностью, ассистент отвечает понятной ошибкой.
3. Запустить:
   ```bash
   docker compose up --build
   ```

- Интерфейс: http://localhost:3000
- OpenAPI: http://localhost:8000/docs

Поднимаются база, Redis, бэкенд, фоновый воркер, фронтенд и оба мока — курсов валют и сервиса маркировки. При первом запуске применяются миграции и заливаются демо-данные.

| Нужно | Команда |
|---|---|
| Остановить | `docker compose down` |
| Начать с чистой базы (демо-данные зальются заново) | `docker compose down -v`, затем снова `docker compose up --build` |
| Порты 3000 или 8000 заняты | `FRONTEND_PORT=3001 BACKEND_PORT=8001 docker compose up --build` |

### Настройки

Все настройки — переменные окружения из `.env`. Для запуска хватает значений по умолчанию; ключ нужен только ассистенту.

| Переменная | Зачем | По умолчанию |
|---|---|---|
| `OPENAI_API_KEY` | Ключ OpenAI для ассистента | пусто |
| `JWT_SECRET` | Секрет для подписи сессий | значение для демо |
| `LLM_PRIMARY_MODEL`, `LLM_FALLBACK_MODEL` | Основная и запасная модели | `gpt-6-luna`, `gpt-5.4-mini` |
| `LLM_REASONING_EFFORT` | Сколько модели «думать»: `none`, `low`, `medium`, `high` | пусто — как решит модель |
| `LLM_SERVICE_TIER` | Тариф OpenAI: `fast` — быстрее и вдвое дороже | пусто — обычный |
| `LLM_STUB` | `true` — заглушка вместо модели, для E2E-тестов | `false` |

## Что умеет

**Учёт**

| Раздел | Что в нём |
|---|---|
| Партии | Реестр: фильтр в каждой колонке, сортировка по клику на заголовок, пагинация на сервере, выгрузка в Excel. Номер партии ведёт в карточку с движениями и историей изменений. Здесь же оформляется поступление: каждая строка становится партией «На проверке» |
| Задания | Черновик → Запланировано → В работе → Завершено; отменить можно только до запуска. В карточке — «светофор» компонентов, резерв по партиям, себестоимость, ввод фактического расхода при завершении и попытки отправки в сервис маркировки |
| Остатки | По каждому материалу: остаток, резерв, свободно, на проверке |
| Журнал | Только для руководителя: кто, когда, что было, что стало |

**Ассистент**

- Отвечает по частям, ответ можно остановить; оборванный ответ сохраняется с пометкой.
- Под ответом видно, какие инструменты вызваны и какая модель ответила. Код Code Interpreter раскрывается, созданные файлы (PNG, CSV, XLSX) показываются в чате и скачиваются.
- Читает данные сразу: остатки, партии и их история, задания, дефицит за период, себестоимость задания и свечи, траты, «хватит ли материалов».
- Меняет данные только через карточку с кнопкой «Подтвердить»: создать и запланировать задание, отменить задание. До подтверждения показывает, что именно сделает.
- Работает с правами текущего пользователя: то, чего нельзя сделать кнопкой, нельзя сделать и через ассистента.
- Считает, строит графики и разбирает загруженные CSV и XLSX в Code Interpreter. Данные попадают туда файлом, который собирает бэкенд, — уже с псевдонимами.
- ФИО сотрудников и названия поставщиков уходят в модель кодами (`EMP-001`, `SUP-001`) и возвращаются в ответе именами.
- Запоминает факты о пользователе («считай в евро»); список и удаление — на странице «Память».
- При 429, 5xx и таймауте основной модели переходит на запасную.

## Как устроено

```
Браузер ──► роутер (разбор запроса, commit) ──► сервис (права, правила, журнал) ──► PostgreSQL
                                                  ▲
Чат ──► маскирование ──► роутер моделей ──► инструмент (проверка аргументов)
                                   действие ──► карточка «Подтвердить» ──► тот же сервис
```

Вся бизнес-логика — в `backend/app/services`. Кнопка и инструмент ассистента вызывают одну и ту же функцию, проверка прав стоит внутри неё. Роутер только разбирает запрос и фиксирует транзакцию.

Промпты — отдельными файлами в `backend/app/assistant/prompts`: системный (`system.md`), описания инструментов (`tools.yaml`), пояснения, которые код добавляет к результатам инструментов и истории (`notes.yaml`), и промпт судьи эвалов (`judge.md`). В коде текстов для модели нет.

```
backend/
  app/
    api/           тонкие роутеры: разбор запроса → сервис → commit
    services/      бизнес-логика: партии, задания, резервы, права, журнал, маркировка
    assistant/     агент, инструменты, маскирование, память, файлы
      llm/         интерфейс к моделям, провайдер OpenAI, переход на запасную
      prompts/     все тексты для модели
    models/        таблицы
    schemas/       входные и выходные схемы
    workers/       фоновая отправка отчётов в маркировку
    seed/          демо-данные
  alembic/         миграции
  tests/           тесты
  evals/           эталонные вопросы и отчёты прогонов
frontend/          интерфейс и E2E-тест
mocks/             мок курсов валют и мок сервиса маркировки
```

| Выбор | Почему |
|---|---|
| Async FastAPI + SQLAlchemy | Долгие ответы модели не занимают потоки |
| arq | Асинхронный, как и остальной код: воркер вызывает те же функции |
| Свой слой над SDK OpenAI | Нужны Responses API, Code Interpreter и точный контроль, что повторять |
| pymorphy3 | Имена узнаются в любом падеже без отправки текста наружу |
| Vite + React | Одностраничному приложению серверный рендеринг не нужен |
| SSE через `fetch` | Поток нужен в одну сторону; `EventSource` не умеет POST |

## Модели

Основная — **`gpt-6-luna`**, запасная — **`gpt-5.4-mini`**. Задаются переменными `LLM_PRIMARY_MODEL` и `LLM_FALLBACK_MODEL`.

Выбирали прогоном кандидатов по своим эталонным вопросам (24.11.2026, судья `gpt-5.4`). Сначала сравнили пять моделей, затем лучшие три прогнали ещё раз:

| Модель | Вопросы без ошибок | Судья | Время на вопрос | Стоимость прогона |
|---|---|---|---|---|
| gpt-5.4-mini | 15/16 | 4,69 | 4,8 с | $0,114 |
| **gpt-6-luna** | **16/16** | **4,94** | 8,5 с | **$0,015** |
| gpt-6.1-terra | 16/16 | 4,94 | 13,9 с | $0,152 |

- `gpt-6-luna` — лучшая по проверкам и в 7–10 раз дешевле соседей по таблице.
- `gpt-5.4-mini` быстрее, но иногда считает в уме вопреки промпту и ошибается. Для запасной этого достаточно; поколение другое, поэтому сбой одной вряд ли заденет вторую.
- `gpt-4.1-mini` в документации OpenAI помечена устаревшей и слабее на файлах; она и `gpt-5-mini` отсеялись в первом прогоне (12 и 11 вопросов из 16).

Оговорка: прогонов мало, ответы моделей меняются от раза к разу; это выбор по имеющимся данным, а не доказательство. Оба прогона с подробностями — в [backend/evals/README.md](backend/evals/README.md#выбор-моделей).

## Качество и скорость ассистента

Последний прогон эталонных вопросов (26.11.2026): **27 из 27**, отдельных проверок 180 из 180, судья 4,93 из 5 — [отчёт](backend/evals/reports/latest.md).

Каждое изменение проверялось замером «до и после» на тех же вопросах. Главное:

| Что сделано | До | После |
|---|---|---|
| Соединение с OpenAI живёт 5 минут вместо 5 секунд — задержка запроса после паузы | 1,26 с | 0,70 с |
| Основная модель молчит — переход на запасную | до 90 с | 20 с |
| Контейнер Code Interpreter один на пользователя, а не на каждый диалог | 8–10 контейнеров на 29 ответов | 3 контейнера на 116 ответов |
| Список файлов контейнера запрашивается, только если код что-то сохранял | 2,6–3,0 с | 0,01 с |
| Опечатки в названиях: «Сколько партий пришло от Васкового двара?» | 1 из 6 | 6 из 6 |
| «Какие задания просрочены?» — определение перенесено в сервис | 5 из 6, ~12 тыс. токенов | 6 из 6, ~8 тыс. токенов |
| «Сколько потратили на воск за месяц?» — отдельный инструмент `get_spending` | 1 из 5, 10–14 с | 6 из 6, 5,7 с |
| «Хватит ли материалов на 300 свечей?» — отдельный инструмент `check_availability` | 13–19 с, 15–26 тыс. токенов | 6,4 с, ~11 тыс. токенов |

- **Куда уходит время.** Ожидание модели — 85–96% времени ответа, наши инструменты — 2–4%. Поэтому вызывать инструменты параллельно бессмысленно.
- **Проверили и не включили.** `reasoning.effort=low` быстрее на 0,6 с, но ошибок больше (51 из 54 против 53 из 54). Быстрый тариф OpenAI быстрее на 0,7–1,4 с, но чаще уводит модель к неверному инструменту. Обе настройки доступны в `.env`.
- **Вывод.** Вопросы, где модель должна угадать период или сделать два вызова, держатся на везении. Чинить надо инструменты, а не промпт.

Полный журнал замеров с условиями и отчётами — в [backend/evals/README.md](backend/evals/README.md#скорость-и-цена-журнал-замеров).

## Решения и допущения

**Учёт**
- Статусы «Принята» и «Брак» окончательные. «На проверке» видна отдельной цифрой и в свободный остаток не входит.
- Курс фиксируется в партии на дату поступления. Если сервис курсов лежит, поступление не создаётся: лучше отказать, чем записать неверную себестоимость.
- Норма расхода — до 3 знаков, как и количества, поэтому потребность всегда точная.
- При планировании потребность копируется из рецепта: правка рецепта не меняет запланированные задания.
- Редактировать можно только черновик. Запланированное — отменить и создать заново либо «Дозарезервировать» после поступления.
- FIFO — по дате поступления, затем по порядку записи. Экономия возвращается в партии, откуда выдавали, начиная с новой. Перерасход без остатка отклоняет завершение с текстом, чего не хватает.
- Фактический расход по умолчанию равен выданному, выпуск вводится отдельно.
- Себестоимость: завершённое задание — по фактическим движениям партий, запланированное — по резерву (с дефицитом помечается неполной), черновик — пробная раскладка FIFO. Себестоимость свечи по рецепту — по средневзвешенной цене свободного остатка. В другую валюту — по курсу на сегодня.
- Права: поступления, статусы партий и материалы — кладовщик и руководитель; рецепты, задания и себестоимость — технолог и руководитель; журнал и повтор маркировки — руководитель; остатки, партии и задания видят все.
- Маркировка: 10 попыток с паузами 5, 10, 20… секунд (до 10 минут), затем «Не удалось» и кнопка у руководителя. Ключ идемпотентности один на все попытки. 4xx (кроме 408 и 429) не повторяются. Мок сначала записывает отчёт, потом «думает» 10 секунд: таймаут на нашей стороне не означает, что отчёта нет, — ровно для этого ключ и нужен.

**Ассистент**
- Действие живёт 30 минут. При подтверждении права и данные проверяются заново; двойной клик безопасен. Массовых действий нет.
- Факт памяти сохраняется без подтверждения: это личная настройка пользователя, а не учётные данные; её видно на странице «Память» и можно удалить.
- На запасную модель переходим, только пока основная ничего не выдала: ответ не склеивается из двух моделей. Ограничения: 5 с на соединение, 20 с до первого события (если есть запасная), 90 с тишины, 180 с на вызов, 8 шагов на вопрос.
- История передаётся моделью целиком (`store=False`), поэтому запасная модель продолжает тот же диалог. Из истории берутся 20 последних сообщений.
- Рабочие заметки модели (`phase: commentary`) в ответ не попадают.
- Контейнер Code Interpreter один на пользователя, а не на диалог: каждый новый контейнер — отдельная платная сессия, а новые диалоги начинают часто. Создаётся только при необходимости; закрылся — пересоздаётся, загруженные в диалог файлы кладутся в него заново. Обычный вопрос контейнер не заводит. Чужих данных в контейнере нет: он у каждого свой.
- Соединение с OpenAI держится открытым 5 минут: новое стоит около полсекунды, а httpx по умолчанию закрывает его через 5 секунд простоя.
- Тариф OpenAI обычный. Быстрый включается через `LLM_SERVICE_TIER=fast`, но по эвалам он хуже выбирает инструменты (см. [замеры](backend/evals/README.md#скорость-и-цена-журнал-замеров)).
- Данные для расчётов модель заказывает инструментом `prepare_dataset`: бэкенд собирает CSV теми же сервисами.
- Картинки по внешним ссылкам в ответе не показываются: через адрес картинки инъекция могла бы вынести данные.

**Персональные данные**
- Псевдоним — id записи (`SUP-001`, `EMP-003`), поэтому он один при любом написании и в любом диалоге. Слова сравниваются по начальной форме.
- Поставщики, которых нет в базе, ловятся по форме («ООО …», «ИП …») и получают код из хэша.
- Однофамилец с другим именем сотрудником не считается, но тоже скрывается. Два сотрудника с одной фамилией без имени — общий код: угадывать нельзя.
- В загруженных файлах маскируется каждая ячейка; из Excel берутся только значения (без формул, примечаний и автора). В CSV и XLSX, созданных кодом, имена возвращаются; на картинке это невозможно, под ней показывается расшифровка кодов.
- Логи: тексты и аргументы не пишутся, значения SQL скрыты, журнал запросов — без строки параметров.

## Дополнительные задачи

## Что не успели и известные ограничения

- Не маскируются люди, которых нет в справочнике сотрудников, фамилии с опечатками и названия в транслитерации. Опечатки прощаются только в названиях поставщиков из нескольких слов (одно слово с опечаткой легко спутать с обычным словом).
- «Остановить» и защита от двух ответов сразу рассчитаны на один процесс бэкенда; для нескольких нужен общий канал в Redis.
- Рецепты и материалы заводятся через API, отдельных экранов для них нет. Нет управления пользователями и смены пароля.
- Интерфейс рассчитан прежде всего на компьютер; на узком экране список диалогов скрыт.
- При удалении диалога его файлы остаются на диске.
- Ответ «курса на дату нет» не кэшируется: для субботы каждый раз идёт лишний запрос.
- Файл с `OPENAI_API_KEY` и `JWT_SECRET` — только локальный `.env`; для продакшена нужны свои секреты и HTTPS (`COOKIE_SECURE=true`).
